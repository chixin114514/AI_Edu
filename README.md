# 慢行 MANXING · 体感自适应城市旅行智能体

根据《体感自适应城市旅行智能体 项目方案书 V2.0》制作的前后端 MVP。支持按城市自动检索地点并生成路线库，打通 **规划 → 开始漫游 → 状态与反馈 → 建议 → 用户确认 → 行程手记**。

前端采用原生 HTML/CSS/JavaScript ES Modules；后端为 Node.js HTTP／HTTPS 服务；数据保存在 SQLite。没有第三方 npm 运行依赖，也无需前端构建。

## 启动

需要 **Node.js 22.21+（22.x）或24.5+**（使用内置 `node:sqlite`，Node 22 会提示实验性警告）。

```bash
cd /root/AIEdu
npm start
```

访问 `http://127.0.0.1:3000`。不需要先运行 `npm install`。无 `.env` 时默认演示模式，无需密钥。本机已写入用户提供的四项服务配置，启用live与 `127.0.0.1:7897` 代理；完整说明见 [服务接入文档](docs/PROVIDERS.md)。

可选配置：

```bash
[ -f .env ] || cp .env.example .env
npm run dev
```

`.env` 不应提交到版本库。数据库首次启动时创建于 `data/manxing.sqlite`。

手机访问需要 HTTPS，配置方法见下节；设备不支持传感器时仍可用手动反馈。

### HTTPS 与手机访问

应用可直接提供 HTTPS，无需额外反向代理。安装 OpenSSL 1.1.1+ 后，生成本地开发证书（将示例 IP 换成电脑实际局域网 IP）：

```bash
npm run https:setup -- --host 192.168.31.132
```

在 `.env` 中设置并重新运行 `npm start`：

```dotenv
HOST=0.0.0.0
PORT=3000
TLS_CERT_FILE=./certs/server.crt
TLS_KEY_FILE=./certs/server-key.pem
```

- 电脑访问 `https://localhost:3000` 或 `https://127.0.0.1:3000`；同一局域网的手机访问 `https://192.168.31.132:3000`，需允许电脑防火墙的 3000 端口。
- 本地证书默认不受其他设备信任。将 **`certs/local-ca.crt`** 安全传到访问设备，在系统／浏览器证书设置中导入为受信任的根证书；iOS 安装描述文件后还需在“证书信任设置”中启用完全信任。仅在自己的测试设备上信任此本地 CA。不要传输 `*-key.pem` 私钥，也不要把跳过浏览器证书警告作为权限验证。
- HTTPS 会自动设置 `Secure` Cookie，并限制最低 TLS 1.2。证书与私钥必须成对配置；读取失败或不匹配时启动失败，不会自动降级。当前端口启用 HTTPS 后，原 `http://…:3000` 地址不再提供页面，不设置 HTTP 跳转。
- 本地服务证书有效期 365 天，包含 localhost、127.0.0.1、::1 和传入的 `--host`，可以重复传入多个主机。IP 改变或证书到期时，用 `--out certs/renewed` 生成新证书，更新 `.env` 并信任新 CA；脚本拒绝覆盖已有目录。
- 正式部署将两个 TLS 路径指向域名的受信任证书完整链与私钥，使用证书对应域名访问；换证后重启。也可以保留 HTTP 后端，由 HTTPS 反向代理终止 TLS，此时设置 `COOKIE_SECURE=true`。
- 清空两个 TLS 变量可恢复 HTTP 开发模式。HTTPS 与 HTTP 属于不同浏览器来源，原 HTTP 的本地缓存不会自动迁移。

本机当前已启用 HTTPS，监听 `0.0.0.0:3000`，证书包含 `192.168.31.132`。证书、私钥、`.env` 均被 Git 忽略。HTTPS 提供安全上下文，蓝牙／运动传感器仍取决于浏览器支持与用户授权。

2026-10-12权限更新后，已通过本机代理完成四项API与两项MCP实测，并启动本地服务。真实浏览器已跑通规划、拒绝／接受改线、打卡和报告；详见测试说明。

## 账号与运营权限

点击右上角“登录 / 注册”进入账号页面，也可直接访问 `/#auth`。游客仍可规划；注册或登录后，本浏览器的游客行程会关联到账号，可跨设备查看。退出后会清除页面内的个人数据和最近行程缓存。

首次启动自动创建管理员：**用户名 `admin`，密码 `admin`**。普通注册账号只有旅行功能，运营入口和 `/api/ops` 由服务端管理员角色保护。旧 `ADMIN_TOKEN` 不再用于运营鉴权。

账号和7天登录会话保存在同一 SQLite 数据库，重启不会重置账号。密码保存为加盐 scrypt 哈希，登录凭据仅放在 HttpOnly Cookie 中，不放入浏览器 localStorage。

## 界面与功能

- **规划旅程**：城市、日期、1／2日、预算、每日时间、同行人、兴趣和步行上限；实况模式自动检索当地地点、按空间聚集和兴趣排序，再以真实步行距离与耗时筛选，预留节点间缓冲。未知票价与开放时间显示待核实，不承诺满足总预算。
- **自动路线库**：生成行程时自动保存城市路线包和地点快照；首页按城市展示最新路线，可查看历史行程、重新规划，刷新页面后仍保留。
- **我的行程**：精简地点清单、逐地点说明、费用与步行汇总、可拖动的真实路线地图、参考来源、雨天候选、历史行程与 JSON 导出。清单可以直接改：点「详情」看这一站的时间、坐标、海拔、接来源与参考人均；「移出」删掉一站；按住右侧把手拖动调整当天顺序；检索到的餐厅也能一键排进当天。**手动改顺序时服务端不会像自动规划那样静默丢站**，超时、超预算、超步行上限或当天闭馆都保留并在提示里说明。
- **高德导航**：每一站都能直接唤起高德导航（步行模式，手机上会尝试打开高德 App）。高德 URI 的途经点只在驾车模式下生效，所以链接按段生成——「导航到这一站」「去下一站」，不提供步行全程导航。
- **途中伴行**：会话、节点打卡、手动疲劳／饥饿反馈、雨天与疲劳趋势演示、建议接受／拒绝、不适暂停。心率与步频直接显示在伴行页上，不需要展开；开始漫游时自动开启步频（iOS 会在这时申请运动权限），失败可以手动重试。
- **漫游日记**：每到一个站点可以写一段文字、配几张照片，照片在本机压到长边 1280 后再保存；手记页会把整程的日记和照片一起列出来。日记与照片只存在自己的账号数据里，不发给模型。
- **Apple Watch＋Safari**：一次性配对码、授权临时心率转发、断流过期与账号隔离；附 watchOS 配套应用源码。原生工程尚待 Mac 编译和真机验证，详见 [安装与使用](apple/README.md)。
- **传感器**：标准蓝牙 Heart Rate Service 读取、8／16位数据解析、接触状态检测、30秒静息参考基线、持续趋势判断；实验性 DeviceMotion 步频；支持浏览器定位、自动识别城市／区县／附近地点，实况模式自动将识别城市填入目的地，随后为该城市生成路线。
- **旅行手记**：打卡、已上报步数推算距离、接受／拒绝次数和事件记录；不将计划距离伪装成实际距离。结束漫游后可以让 DeepSeek 按这次真实走过的行程写一段收尾文字——只发送城市、日期、地点名与类别，不发送坐标和任何健康数据。
- **运营工作台**：地图、天气与模型服务的配置状态和最近调用结果；可主动测试地图步行路径与天气实况，查看返回摘要、耗时和错误码。仅管理员账号可使用。
- **数据控制**：账号／游客 HttpOnly Cookie 隔离、模型分项授权、停止传感器、删除本人数据、缓存最近行程供离线查看。Service Worker 只缓存前端静态文件，不缓存接口响应。

## 演示建议

1. 使用 `2026-10-13`、一日、09:00—18:00、6公里、300元生成行程（该日期仅用于可重复演示）。
2. 查看路线与 Plan B，点击“开始漫游”；模型授权可不勾选。
3. 点击“轻松一点”，查看新增／跳过地点和距离、时间差；拒绝时原路线不变。
4. 再次提出建议并接受；行程版本更新。可以用“模拟下雨”或“模拟疲劳趋势”展示事件触发。
5. 完成节点打卡、结束漫游，查看并导出手记；手记页可以点「写一段收尾文字」让模型按这次行程写一段，也可以回看每一站的日记与照片。
6. 在「我的行程」里按住站点右侧的把手拖动改顺序，或点「移出」删掉一站，看看步行总量与结束时间跟着变；超约束时界面会如实提示而不是悄悄删站。
7. 点击右上角「登录 / 注册」，使用 `admin / admin` 登录后进入运营工作台；普通注册用户看不到运营入口，也不能调用运营接口。

## 数据和外部服务

| 能力 | 默认行为 | 配置后行为 |
| --- | --- | --- |
| 步行距离／耗时 | 明确标注的演示估算，不能用于导航 | `DATA_MODE=live` + `AMAP_MAPS_API_KEY` 调用高德步行接口；失败返回503，不静默伪造实况路线 |
| 天气 | 演示天气 | 杭州优先和风实况、失败回退高德；其他城市按行政区查询高德实况，不使用杭州天气，不冒充未来旅行日预报 |
| 行程说明 | 规则模板 | 有 `DEEPSEEK_API_KEY` 且用户授权时调用 DeepSeek JSON Output；校验失败或超时回退模板 |
| 快速决策 | 规则引擎 | 有 `TYPESAFE_API_KEY` 且会话授权时，调用TypeSafe官方接口；模型结果只作为参考，不越过规则与确认边界 |
| POI事实 | 32条未核验样本 | 行政区查询 + 高德POI 2.0检索，最多50个去重候选；真实名称、坐标与来源，营业、票价和预约仍需核实 |
| 公交换乘／地点检索 | 不可用（明确提示需要实况服务） | `DATA_MODE=live` + `AMAP_MAPS_API_KEY` 调用高德换乘与地点检索；无方案或鉴权失败返回503，不回传上游错误正文 |
| 海拔与坡度 | 按坐标或当天站点查询（公开服务，无需密钥，演示模式同样可用） | Open Topo Data 公开 SRTM 90 米服务；排队限速、结果缓存 24 小时，缺口返回 null 不按 0 米补齐 |

`DEEPSEEK_MODEL` 可配置，默认值按开发时官方JSON示例设置为 `deepseek-flash`，应以账户实际开放型号为准。API 密钥仅在后端。

**Jev已按官方HTTP协议实现**，模型为 `jev-1.13.0`。密钥已配置，TypeSafe官方调用及网页流程已真实验证。旧自建网关变量仅作兼容备用。

## 对方案书的实现范围

这是可运行的第一版原型，以下功能还未完成正式交付：

- 实况路线采用动态POI检索、聚集与兴趣排序、时间及步行约束筛选；演示模式保留杭州模板。DeepSeek只生成说明。已支持：必去节点锁定（最多3个，排在最前保证不被挤掉，排不进去时给出原因）、自定义起点与终点（含"用当前位置出发/回到当前位置"）、午间用餐窗口（实况模式下路线跨过 11:30—13:30 且无餐饮节点时就近插入一家）、地点选择器（按名称在城市范围内检索高德地点，用来挑起点、终点或必去节点）。尚未实现全局多目标优化与完整用餐时间窗求解。
- 步行之外的接驳已接入高德公交换乘：在行程页选择任意出发地与目的地（当前位置、当天站点，或搜索到的其他地点），返回按耗时排序的方案，包含票价、步行距离、换乘次数与逐段乘坐方式。仅支持同城换乘，票价为首程参考，首末班与拥挤度需现场确认。
- 坡度与爬升用 Open Topo Data 的 SRTM 90 米高程样本估算：可查当前定位点的海拔，也可按天计算路线累计爬升／下降、最低最高点与逐段坡度，并列出需要留意的坡段。它是网格高程不是实测坡度，台阶、隧道和桥面不会体现；查询前会把项目内的 GCJ-02 坐标反解为 WGS-84。交通延误订阅与分钟降水／天气预警的自动推送仍未实现，雨天自动建议使用显式演示按钮。
- 路线一览使用高德静态地图真实底图，叠加实况步行接口返回的道路折线与地点编号。支持手机单指滑动、鼠标拖动、方向键平移，以及放大、缩小、全程视图、地点聚焦和跳转高德。松手后加载对应区域，缩放保留当前中心；暂不支持双指缩放或实时导航。已有行程可直接显示，演示数据只显示地点、不伪造步行路径。
- 实况POI名称与坐标来自高德；高德当日营业文字不能证明未来日期开放，因此当前规划仍为待核实草案。未知票价不当成免费，预算只限制已知费用；室内属性由类别推断，停留时长为规则估计。
- 步频算法需实机校准。心率阈值为产品演示规则，未做医学或疲劳识别有效性验证；不输出伪造的规则置信度。步频在开始漫游时自动申请权限，桌面浏览器没有 `DeviceMotionEvent` 时静默跳过。
- 手动改顺序不做全局优化：它就是用户给的顺序，服务端只重算每段的步行与时间，并把超出约束的地方列出来。漫游进行中不允许改顺序（会话的 `current_index` 指向具体节点），需要先结束本次漫游。
- 日记与照片和行程放在同一份存储里（网页端 SQLite、App 端设备存储），单张 2MB、每个地点 6 张，只适合原型规模：没有对象存储、没有缩略图、没有跨设备同步。照片按用户压缩后的原样保存，服务端只校验文件头，不做内容审核。
- 收尾文字沿用规划时的模型说明授权（它是行程内容，不是健康内容），没有单独再设一个「文学内容」授权项；未授权时界面说明原因而不是偷偷调用。
- 页面打开后自动请求一次定位授权，允许后经高德将WGS84转换为GCJ-02并识别地址，实况模式自动填入省市区。拒绝或失败时可手动选择；切换页面不重复请求，手动修改的目的地不会被迟到的定位结果覆盖。起点可用"当前位置"或其他坐标指定，未指定时由城市候选地点自动选择；起点之前与终点之后的交通不计入徒步量。定位不用于自动打卡，不发给模型、不落库或缓存。手机定位需要HTTPS；本机可通过localhost或127.0.0.1体验。
- 应用进入后台后不再强行清空趋势窗口（原实现为避免用断档数据触发建议）；Android 端由前台服务保活，锁屏或切后台后心率与定位可继续记录，网页端仍按浏览器的冻结行为处理。iPhone Safari和iPhone Chrome均不能默认获得网页蓝牙能力。
- 没有支付、库存、客流、评论抓取、多人协同和跨设备同步。
- SQLite和内存请求锁面向单实例演示。公开部署前需补齐正式身份、持久化限流、数据库事务审计、数据保留策略、监控与备份。
